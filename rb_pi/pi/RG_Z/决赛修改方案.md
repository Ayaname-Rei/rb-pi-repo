## 0. 一页结论（TL;DR）

**决赛的第一风险不是速度，是"瘫痪"**：现有代码在对方车在场时有 4 个能把整场归零的 P0 缺陷；
其中 3 个是代码问题（可修），1 个是流程依赖（搬车窗口是否还合法，需和规则确认）。
仿真显示：只要把"任何异常→整场中止/死循环"改成"任何异常→降级继续"，在对手抢块场景下
平均分从 **8.3 分提升到 186.4 分**（满分 230），而在空场场景零损失。

| 优先级 | 改动 | 改哪 | 预计工作量 | 收益（仿真） |
|---|---|---|---|---|
| **P0-1** | MissionAbort 分级降级（失败只弃当前遍，不弃整场） | motion_client.py | 半天 | O2 场景 +178 分 |
| **P0-2** | 巡航被顶住检测（堵转→停车报警，不无限推） | motion_client.py | 2 小时 | 消除"顶对方车到比赛结束" |
| **P0-3** | 视觉类名精确匹配（现在会把塔当橙块，可能扒自己的塔） | vision_server.py | 10 分钟 | 消除自拆塔 |
| **P0-4** | **规则确认：遍间 20s 人工搬车窗口决赛是否允许** | 流程，不是代码 | 0 | 决定主策略是否成立 |
| P1-1 | 扫描/对齐有界化 + 抓取失败不进入搭建 | motion_client.py | 半天 | 保底 180 分地板 |
| P1-2 | 视觉帧时间戳 + 陈旧帧丢弃 | vision_server.py + motion_client.py | 2 小时 | 消除"冻结旧帧秒对齐" |
| P1-3 | 多目标消歧（面积门限 + CONFIRM=2~3） | vision_server.py + config | 1 小时 | 对方车入镜不锁错 |
| P2-1 | 决赛提速包（巡航 0.6→0.8，撞墙不动） | config.py | 1 小时 + 实测 | 全程 -12.8s，镜像对手近乎必胜 |
| P2-2 | 搭建后置 / 机会主义抓取 | 主流程 | 大 | 收益小，**默认不做**（见 §4） |
| P3 | 避障感知 / 防拆塔 / 双代码合并 | 新能力 | 天级 | 路障场景目前所有策略免疫（均分 12~30），只有感知能救 |

## 1. 事实基础：哪套代码是实际比赛入口

仓库里存在**两套并行主控**，修改方案必须落在真正上场的那套上：

| 代码 | 最后修改 | 入口 | 状态 |
|---|---|---|---|
| `raspberrypi/motion_client.py`（84KB，29 阶段） | **10-03 13:19** | `start_robot.sh` → `motion_client.py --stage 1x3` | **实际比赛主代码** |
| `robogame_mission/run_mission.py`（23 步） | 10-02 12:38 | 手动运行 | 旧主线 / 备用 |

证据：顶层 `start_robot.sh`（10-03 10:32）指向 `/home/pinqu/RG/raspberrypi`，注释明确
"1x3=第一大段（阶段 1~9）连做三遍（默认，比赛用）"。

**实际比赛流程（1x3 模式）**：

```
第 n 遍（n = 1..FIRST_SECTION_PASSES=3）:
  stage1_grab_purple   (巡航→撞墙→视觉对齐→抓紫)
  stage2_grab_orange   (转场→撞墙→视觉对齐→抓橙)
  stage3_return_and_build (返场→搭建 3 层)
  → 车原地静止 20s（REPLACE_STILL_SECONDS）
  → 现场向裁判申请异常处理，人工把车搬回启动区
  → odom_reset 清零，从 stage1 重跑
```

两套代码共用 `orangepi/vision_server.py`（香橙派视觉节点，TCP 推送 found/aligned/eu/ev）。

## 2. 仿真结果摘要（详见 `simulation/RESULTS.md`）

Monte Carlo 5 万次（5 对手 × 5 策略 × 3 时限 × 2 计分权重）。对手模型：
O0 空场 / O1 镜像对手 / O2 专职抢块 / O3 专职搭塔 / O4 路障（停在我方路线上）。

### 策略 × 对手 平均得分（300s 时限，基准计分，满分 230）

| 策略 | O0 空场 | O1 镜像 | O2 抢块 | O3 抢搭 | O4 路障 |
|---|---|---|---|---|---|
| V0 现有初赛代码 | 230.0 | 154.9 | **8.3** | 230.0 | 30.3 |
| V1 有界扫描（失败降级继续） | 230.0 | 219.7 | **186.4** | 230.0 | 28.4 |
| V2 = V1 + 搭建后置 | 230.0 | 225.4 | 186.7 | 230.0 | **12.4 ↓** |
| V3 = V2 + 提速 | 230.0 | 229.8 | 192.9 | 230.0 | 12.6 |
| V4 = V3 + 机会主义抓取 | 230.0 | 230.0 | 195.8 | 230.0 | 12.3 |

关键数字：

1. **V0 在 O2（对方专职抢块）下死循环率 100%**——低位橙扫描段块一旦被抢走就无限循环顶墙，
   得分冻结至比赛结束，平均 8.3 分。O1（镜像对手）下死循环率 33%，得分双峰（≈230 或 ≈0），
   取决于谁先抢到第一块；若双方同时出发，V0 就是 50/50 赌局（均分 112.6）。
2. **"失败降级继续"（V1）是收益最大的单点改进：O2 下 +178 分，空场零损失**。
3. **"搭建后置"（V2）在路障场景有反作用**（30.3→12.4 分）：碰撞截断在路线后段时，
   后置的 90 分塔分连带损失。**建议维持现有搭建时机**，只做 V1+V3。
4. **O4 路障对所有流程类改进免疫**（所有策略均分 12~30，中位数 0）：
   撞上停着的对方车后机器人到不了任何资源区，逻辑兜底全部失效。
   对抗路障需要感知能力（P3），与扫描策略正交。
5. 时限 240/300/360s 下结论稳定；计分权重改为"塔×2/块×0.5"时保底搭建的价值进一步放大
   （V1 在 O2 下 363 分 vs V0 的 8.6 分）。

**仿真口径说明**：耗时参数取自 23 步流程的代码实测值（任务书分段累加 ≈213s，中位完成 210s），
与 1x3 实际流程的阶段结构不同，但两类代码的**失败模式相同**（扫描循环、撞墙歧义、返回值处理），
方向性结论可直接迁移。决赛规则确认后可在 `simulation/sim_core.py` 参数区重标定复算。

## 4. 修改方案（按批次给出具体改法与验收标准）

### 第一批：赛前必做（合计约 1~1.5 天，全部不破坏初赛已验证的路线）

#### M1 · 视觉类名精确匹配（10 分钟，消灭自拆塔）
`orangepi/vision_server.py:20-28`：

```python
# 改前
purple = [d for d in dets if "purple" in d["name"].lower()]
orange = [d for d in dets if "orange" in d["name"].lower()]

# 改后
purple = [d for d in dets if d["name"] == "Purple_Block"]
orange = [d for d in dets if d["name"] == "Orange_Block"]
```

验收：把 Orange_Tower 纸盒放在画面里，确认 orange_low/orange_high 通道不再 found=true。

#### M2 · MissionAbort 分级降级（半天，**本方案核心**）
原则：**任何一段失败只损失"这一遍"，绝不损失整场**。3 遍 = 3 次机会，现在的代码把 3 次机会
合并成了 1 次。改 `motion_client.py` 的 `run_first_section_thrice`：

```python
for n in range(1, FIRST_SECTION_PASSES + 1):
    if n > 1:
        ...  # 现有的 20s 等待 + clear_all_records 不动
    state = MissionState()
    try:
        stage1_grab_purple(chassis, arm, state)
        stage2_grab_orange(chassis, arm, state)
        stage3_return_and_build(chassis, arm, state, pass_no=n)
    except MissionAbort as e:
        print(f"#  第 {n} 遍中止：{e} —— 车已安全停车，等待下一遍/收尾")
        # 车内嵌的异常处理已发 stop；这里不再 re-raise
        # 若是最后一遍则自然退出；否则落入现有的 20s 等待窗口
        continue
```

同时保留 main 层对 `ChassisLinkLost` 的最终兜底（链路彻底没了才真的退出）。
注意点：
- stage1 失败时车停在半路，20s 窗口的搬车流程照常把它搬回启动区 → 与现有"搬车回启动区"语义天然兼容；
- stage3 失败（已搭一部分）时同样停车等窗口；
- `state` 每遍新建的现有设计不变。

验收：人工在 stage2 视觉段挡车 5 秒触发 MissionAbort，确认打印"第 1 遍中止"后车静止、
20s 后清零并开始第 2 遍，而不是进程退出。

#### M3 · 巡航堵转/顶住检测（2 小时）
`motion_client.py` 的 `run_segments_sequence` 循环内（:377-390 附近）加第三重守卫：

```python
# 指令速度非零但里程速度持续低于阈值 → 被顶住/卡死，停止推挤
if (seg 指令速度 > 0.05) and (abs(odom vx)+abs(vy)+abs(wz) < 0.02 连续 2.0s):
    raise MissionAbort(f"{seg['name']} 被阻挡 2s，停止推进")
```

由 M2 的降级层接住。**这同时是规则保护**：无限顶对方车在多数规则下是犯规/危险行为，
检测到阻挡后停车等待远优于持续推挤。
验收：人工挡在巡航路线上 2 秒，车应停车报警（打印），30s 后确认无位移不再尝试。

#### M4 · 规则确认：遍间搬车窗口（0 代码，最高优先级去问）
决赛若**允许**异常处理搬车 → 1x3 策略成立，M2/M3 直接生效。
决赛若**不允许** → 1x3 模式作废，退到 `--stage all`（完整 29 阶段自主流程），
此时 M2 的 try/except 要改包在 `run_all_stages` 外层，且仿真中的"3 次机会"收益消失，
应重跑仿真评估单遍满流程的风险。**这条不确定前，其余优化都不要定稿。**

### 第二批：对抗丟分防护（合计约 1 天）

#### M5 · 扫描/对齐有界化（半天，对应仿真 V1）
现状：raspberryi 版已有 3s 无进展保护（motion_client.py:619），但触发即整场中止；
M2 落地后它自动变成"段级中止"，本条已解决大半。补两件事：
- `detect_move` 增加总尝试时长上限（如 30s/段），防止"每次都挪 2.9s"的软死循环；
- stage1/stage2 抓取失败（MissionAbort 或超时）时在 `state` 里记录
  `grab_purple_ok / grab_orange_ok`。

#### M6 · 搭建按抓取成败裁剪（2 小时，对应仿真"180 分地板"）
stage3 依据 M5 记录的成败标志裁剪动作组序列：块没抓到就不执行对应的取放/搭建动作组，
避免对空框"隔空取物"撞倒已搭层。需要先对照 `raspberrypi/arm/action_groups/` 的
Id 表确认每个 BUILD 动作组消耗哪一块，再做映射。
**注意**：若决赛规则是"建塔不耗块"（初赛仿真反推如此），裁剪只影响动作安全性、不影响得分，
仍值得做（防倒塔）。

#### M7 · 视觉帧新鲜度（2 小时）
- `vision_server.py`：latest_data 加 `ts = time.monotonic()`；
- 客户端解析处：`ts` 超过 0.5s 的帧按 found=false 处理（等价于"看不见"，车会按无进展保护停车，而不是按旧帧"对齐"）。

#### M8 · 多目标消歧（1 小时）
- find_orange/find_purple 增加**面积窗口**：`8000 <= area <= 60000`（按实测块大小定，
  排除远处小块噪声和贴脸对方车身）；优先选**离 target 椭圆最近**的框而非最大/最右；
- `config.py`：`CONFIRM` 1→2（连续 2 帧对齐才停车），代价每段 +0.1s，换来误检率大幅下降。

### 第三批：策略调优（仿真支持，但放最后——先保证"不瘫痪"）

#### M9 · 决赛提速包（1 小时改 + 半天实测，对应仿真 V3）
- `config.py`：巡航 VEL 0.6→0.8、GRAB_SPEED 0.10→0.15（扫描段）；
- **撞墙参数一律不动**（堵转判停与速度耦合，动了会破坏定位基准）；
- 必须实车验证：0.8m/s 下拐点混合、撞墙接近段的过冲是否可接受。
- 仿真收益：全程 -12.8s；镜像对手场景近乎必胜（229.8 vs 对方 0.8，因为对方 V0 逻辑会
  被我们先抢到块逼进死循环）；抢块场景多抢回 ~6 分。

#### M10 · 不建议做（除非规则反转）
- **搭建后置（V2）**：仿真显示它在路障场景把均分从 30 砍到 12（得分风险后置），
  且收益（+5.7 分）远小于实现风险（机械臂携 5 块未验证）。默认不做。
- **完全重排抓取顺序（先橙后紫）**：破坏全部撞墙定位基准，等于重推开环路线，不可行。
- **机会主义抓取（V4）**：收益最小（+2.9 分），且需要重写扫描逻辑，性价比最低。

### 第四批：能力建设（时间允许才做）

## 5. 决赛规则确认清单（拿不准就问组委会，直接影响方案取舍）

1. 比赛时限？（仿真对 240/300/360s 均稳健，但影响提速的边际价值）
2. 计分：块/塔层各多少分？紫块是否计分？**建塔是否消耗块**（影响 M6 与保底策略）？
3. 场上积木是双方共享吗？对方能否拆/推我们已搭的塔？
4. **初赛的"异常处理 + 搬车回启动区"窗口决赛是否仍然允许？次数？**（决定 1x3 主策略生死）
5. 碰撞规则：推搡/阻挡对方是否犯规？（决定 M3 停车 vs 绕行的取舍）
6. 场地尺寸/墙位与初赛是否一致？（撞墙基准全部依赖）

## 6. 决赛日赛前实测清单（15 分钟，全部对应上面的修改项）

1. **odom 轴向 10 秒测试**（决定 R9 是否成立的最终证据）：车右转 90° 后手动 `move` 前进，
   看 rel_x/rel_y 哪个变化 → 若 rel_x 不变则确认世界系（robogame_mission 版不可用）。
2. **M2 演练**：手动挡车触发一次 MissionAbort，确认降级到下一遍而非退出。
3. **M3 演练**：巡航段挡车 2 秒，确认停车报警不推挤。
4. **M1/M8 演练**：人/纸箱站进相机画面，确认不锁错目标。
5. **急停演练**：`pkill -9 -f motion_client.py`（start_robot.sh 注释里写明的急停方式），
   确认底盘停、臂卸力。注意 q 键**不是**全局急停（只退当前视觉段，车会继续动）——
   现场操作手册必须写 pkill。
6. 摆位复核：1x3 模式握手即清零，摆位必须精确在启动区原点。
