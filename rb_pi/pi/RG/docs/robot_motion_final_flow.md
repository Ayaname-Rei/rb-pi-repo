# 机器人决赛新版全流程（Phase 1–9）运动与控制详解

> **文档说明**：本文档记录决赛新版流程 **Phase 1 ~ Phase 9** 的全部底盘移动、撞墙定位、视觉微调、机械臂动作与**跨阶段动态决策逻辑**，作为 `motion_client.py` / `config.py` 改写与现场标定的对照依据。
>
> 与预赛版（`robot_motion_29_stages.md`，29 阶段）的**根本区别**：新版不是一条写死的固定动作链，而是在 Phase 4 与 Phase 8 各有一处**依据实际抓取结果分支**的搭建逻辑——抓到几个块就搭几层，中间框永远优先，两侧框的块必须先移入中间框。因此**抓取结果必须逐块记录并跨阶段传递**。
>
> **全局参数本次一律不变**（见下节），改的只是流程编排。

---

## ⚙️ 全局核心参数（保持不变）

底盘与视觉在整个流程中遵循以下基础参数：

*   **直线巡航速度（`VEL`）**：最高 `0.60 m/s`
*   **减速参数（`SLOW`、`DECEL`）**：距离本段目标 `0.10 m` 时开始降速，降速段速度为 `0.20 m/s`
*   **转弯参数（`TURN_TIMEOUT`、`TURN_SETTLE`）**：单次转弯最大超时 `5.0 s`，转弯完成后原地稳定等待 `0.5 s`
*   **板端到位容差**：`yaw_tol = 0.030 rad`（约 `1.7°`）、`pos_tol = 0.005 m`
*   **视觉抓取微调（`GRAB_SPEED`、`GRAB_MAX`）**：检测速度 `0.05 m/s`，单次最远盲探 `0.90 m`；未检测到则**反向**再探一次（`detect_move` 的 timeout → 反向重试）
*   **微调期间的航向保持**：视觉微调与抓取的**整段**（含两次前后盲探与机械臂动作）显式设为 `heading_hold,0`，段末恢复 `1`。理由见下文「视觉微调与抓取」。
*   **对齐确认（`CONFIRM`）**：连续 `1` 帧收到 `found && aligned` 即判定到位并停车
*   **撞墙堵转判定**：目标方向速度 `< 0.02 m/s`、坐标移动 `< 0.005 m`，持续 `0.4 s` 即判定撞墙成功并停车；**所有撞墙段末端限速 `0.10 m/s`**
*   **视觉预热**：启动后 `WARMUP_SECONDS = 10 s`；切换摄像头后额外等待 `1.5 s` 预热
*   **保护阈值**（沿用，不改）：直线行程上限 `位移 × 1.5 + 0.3 m`；转弯无进展 `1.5 s / 0.02 rad`；转弯实测复核容差 `10°`；撞墙硬超时 `10 s`；链路恢复等待 `20 s`
*   **微调顶墙判定**：视觉前后盲探中，位置在 `1.5 s` 内增长不足 `0.005 m` 即判定顶住障碍，**停车并把本次扫描按「未探到」结束**（不中止整轮）。理由见下文「视觉微调与抓取」。

## 📐 坐标系、零点与航向约定

### 指令坐标系

**所有移动指令一律使用车体坐标系**（与 `core/protocol.py` 的 `move` 命令一致）：

| 指令 | 车体向量 | 含义 |
| --- | --- | --- |
| 前进 / 后退 | `+x` / `-x` | `vx = ±1.0` |
| 左移 / 右移 | `+y` / `-y` | `vy = ±1.0` |

*   直线平移与原地旋转**严格互斥**（`vx/vy` 与 `wz` 不同时给），不使用斜向运动。
*   转向角度**正值为左转、负值为右转**，由 A 板 `move,0,0,dyaw` 陀螺仪硬件闭环执行。
*   里程计（`rel_x` / `rel_y` / `rel_yaw`）为**世界坐标系**，与车体指令相差一个当前航向的旋转——这是撞墙段早年算飞过的根因（`run_wall_hit` 现用位移模长 `hypot` 测距，与朝向无关）。

### 三个绝对零点

本流程全程只建立 **3 个绝对零点**，每次 `odom_reset` 之后**此前的一切绝对坐标作废**：

| 零点 | 建立时机 | 用途 |
| --- | --- | --- |
| **Z1** | Phase 1 末尾「右移 0.6 m 撞墙」 | Phase 3 的绝对复位目标（Z1 沿前后轴退 0.6 m） |
| **Z2** | Phase 5 末尾「左移 0.5 m 撞墙」 | Phase 6 开头的倒车复位目标 |
| **Z3** | Phase 6 末尾「左移 1.2 m 撞墙」 | Phase 7 开头的复位目标 |

> Phase 3 末尾的两段撞墙**不重置零点**（其后 Phase 4 只有机械臂动作，Phase 5 全部是相对位移），Phase 7 末尾同理。

### 各阶段航向

| 阶段 | 起始航向 | 阶段内转向 | 结束航向 |
| --- | --- | --- | --- |
| Phase 1 | `0°` | 左转 90° | `+90°` |
| Phase 2 | `+90°` | — | `+90°` |
| Phase 3 | `+90°` | 左转 90° | `+180°` |
| Phase 4 | `+180°` | — | `+180°` |
| Phase 5 | `+180°` | 左转 180° | `0°` |
| Phase 6 | `0°` | 右转 90° | `−90°` |
| Phase 7 | `−90°` | 右转 90° | `−180°` |
| Phase 8 | `−180°` | — | `−180°` |

**三段「绝对复位」一律沿里程计 X 轴闭环**——注意上表的航向是**启动区坐标系**里的角度，不能直接拿来推闭环轴。真正的依据是 `odom_reset` 的语义：

> `odom_reset` 把**位置和航向一起**清零（A 板协议：`rel_x = rel_y = rel_yaw = 0`，驱动 `core/chassis_driver.py` 的 `_wait_odom_zeroed()` 还会复核 `rel_yaw`）。因此每次清零后，**里程计 `+x` 就是「清零那一瞬间的车头方向」**——这是个会跟着车一起转的坐标系。

三处复位都发生在「上一次 `odom_reset` 之后还没转过弯」的时刻（Phase 2 / 5 / 6 的视觉微调只沿前后轴挪车，不转向），此刻 `rel_yaw ≈ 0`，于是：

| 复位段 | 清零时刻的 `rel_yaw` | 车身前后轴 = 里程计 | 闭环轴与目标 |
| --- | --- | --- | --- |
| Phase 3 开头 | `≈ 0` | **X 轴** | 里程计 `X` 轴，目标 `X = −0.60` |
| Phase 6 开头 | `≈ 0` | **X 轴** | 里程计 `X` 轴，目标 `X = 0`（Z2 原点） |
| Phase 7 开头 | `≈ 0` | **X 轴** | 里程计 `X` 轴，目标 `X = 0`（Z3 原点） |

> **所以 `move_abs_y()` 不需要了**：三处复位全部沿里程计 X 轴，一个 `move_abs("x", 目标)` 三处都能直接用。已实现为泛化形式 `move_abs(axis, target)` 并带一道轴向自检（`|cos(rel_yaw)|` 小于 `MOVE_ABS_PROJ_MIN` 就拒绝起步），因为若以后在复位前插入转弯，闭环轴会跟着变。
>
> ⚠️ 早先按「车头 `+90°` → 闭环 Y 轴」的推法是**错的**：那用的是启动区坐标系的角度，而里程计坐标系在每次清零时已经重新锚定到当时的车头方向了。

## 🔗 跨阶段状态记录（Phase 4 / Phase 8 的依据）

新版流程必须在运行期维护下表状态，**不得依赖写死的层数**：

| 变量 | 产生阶段 | 消费阶段 | 含义 | 来源 |
| --- | --- | --- | --- | --- |
| `grab_near_L` | Phase 2 | Phase 4 | 第 1 块（→左框）是否识别并抓取成功 | `detect_move` 返回 `"aligned"` |
| `grab_near_M` | Phase 2 | Phase 4 | 第 2 块（→中框）是否识别并抓取成功 | 同上 |
| `grab_near_R` | Phase 2 | Phase 4 | 第 3 块（→右框）是否识别并抓取成功 | 同上 |
| `k` | Phase 4 | Phase 8 | Phase 4 实际搭建的层数，`0 ≤ k ≤ 3` | Phase 4 决策结果 |
| `grab_purple` | Phase 5 | Phase 8 | 高台紫块是否识别并抓取成功（→左框） | 同上 |
| `grab_far_M` | Phase 6 | Phase 8 | 远侧第 1 块（→中框）是否成功 | 同上 |
| `grab_far_R` | Phase 6 | Phase 8 | 远侧第 2 块（→右框）是否成功 | 同上 |

**判定口径**：香橙派视觉节点持续推送三类目标的 JSON 状态 `{purple, orange_low, orange_high}`，每类含 `found / aligned / eu / ev`。树莓派侧以 `detect_move()` 的返回值为准——返回 `"aligned"` 才算「识别到了这块并可以抓」，返回 `"timeout"` 记为未抓到。**抓取失败不是异常路径**，是设计好的降级路径，不得中止流程。

**帧陈旧防护**：每抓走一块后，必须调用 `_wait_lock_release(target_type)` 等视觉放开对上一个目标的锁定，再开始下一次定位。否则 `CONFIRM = 1` 会让 `detect_move` 拿到上一块残留的「已对齐」旧帧、一步没动就原地返回 `aligned`，而日志与真实检测完全一样、看不出来。

**顶墙即结束本次扫描（不中止整轮）**：前后盲探时若车已经顶住障碍（位置在 `GRAB_NO_PROGRESS_S = 1.5 s` 内增长不足 `0.005 m`），立即停车并把本次扫描按「未探到」返回 `"timeout"`，与「走满 0.90 m 未探到」走同一条路径。由此天然接上既有的反向重探逻辑：

| 碰墙发生在 | 结果 |
|---|---|
| **前进** | 返回 `timeout` → `find_block` 对**同一块**做反向再探一次 |
| **后退** | 返回 `timeout` → `find_block` 返回 `timeout` → 放弃这一块、记 `False`、转下一块 |

碰墙是正常的物理结果，不是异常。**绝不可用 `MissionAbort`**：它会一路冒泡出 `main()` 触发 `sys.exit(2)`，等于「微调顶到墙」直接判整场比赛结束。

**微调期间关闭航向保持（`heading_hold,0`）**：视觉微调与抓取的**整段**都显式关闭 A 板的航向保持，段末恢复 `1`（见 `heading_hold_off`）。原因是微调的目的就是精确贴近方块，而航向保持会在车慢慢挪动时不停修正车头，带来说不清的横向偏移，`u` 值跟着跑、抓取位置就偏。覆盖范围含机械臂动作那几秒——臂一动会扰动车身，此时若还开着航向保持，A 板会反过来推底盘去找回原航向。恢复必须走 `try/finally`：中途抛异常也要保证 A 板回到已知状态。

**一个有用的不变量**：Phase 4 的决策表（见下）在任何输入组合下都会**把抓到的块全部用掉**——Phase 4 结束时机上左/中/右侧框均为空。因此 Phase 5 放入左框的紫块、Phase 6 放入中框/右框的橙块，来源都是干净的。

## 🟢 Phase 1：从启动区到近侧橙色物料区（建立零点 Z1）

**目的**：抵达近侧橙色物料区，并把撞墙点确立为全流程第一个绝对基准。

### 路线巡航（车体坐标系，段间停稳）

1. 前进 `0.70 m`
2. 右移 `0.20 m`
3. 原地左转 `90°`（航向角 → `+90°`）
4. 右移 `0.60 m` **撞墙**（匀减速：右移 `0.50 m` 时速度降到 `0.10 m/s`）
    *   减速距离 `0.50 m`，行程上限 `0.60 m`，末端速度 `0.10 m/s`——即最后 `0.10 m` 以 `0.10 m/s` 爬行贴墙。

### 撞墙定位

*   右移撞墙成功（堵转判定）后停车，随即 **`odom_reset`：把当前撞墙位姿定为绝对零点 Z1 `(0,0,0)`**。
*   复位确认失败时按现有策略**打印偏移量警告后继续**，但后续按绝对坐标规划的动作会带着这个偏差，操作员需据此判断本轮是否仍可用。

**起点默契**：程序启动握手已把「车当前所在处」清零，因此 Phase 1 的路线从 `(0,0,0)` 出发。

## 🟢 Phase 2：视觉定位并抓取三个橙色块（记录抓取情况）

**摄像头**：**高位摄像头**（视觉目标 `orange_high`、`camera = "high"`）。

**动作序列**：三次「视觉定位 → 抓取 → 入框」，每次的入框位置不同：

| 次序 | 视觉微调 | 机械臂动作 | 入框 | 状态变量 |
| --- | --- | --- | --- | --- |
| ① | 沿车身前后轴前进/后退定位色块 | **Id7**（近侧橙块 → 左侧框） | 左侧框 | `grab_near_L` |
| ② | 同上（抓完 ① 后等视觉释放锁定，再从当前位置重新定位） | **Id9**（近侧橙块 → 中间框） | 中间框 | `grab_near_M` |
| ③ | 同上 | **Id8**（近侧橙块 → 右侧框） | 右侧框 | `grab_near_R` |

*   **视觉微调方式**：`detect_move(vx = ±0.05 m/s, dist = 0.90 m)` 前后移动，色块落入椭圆（`aligned`）即停车；前进探不到则后退同样距离再探一次；任一侧顶到墙则当次扫描立即结束（见上文「顶墙即结束本次扫描」）。整段微调与抓取在 `heading_hold,0` 下执行。
*   **动作组选择依据**：对照表里「**近侧**橙色块」正是「从车身右侧抓取」的 `Id7 / Id8 / Id9`，与 Phase 1 撞墙后物料在车身右侧一致；三者按入框位置分别是 左 = `Id7`、中 = `Id9`、右 = `Id8`。
*   **记录**：每次抓取后立即写回上表状态变量（`aligned` → `True`，`timeout` → `False`），供 Phase 4 读取。**这是本阶段的核心产出**，抓没抓到决定了 Phase 4 能搭几层。

## 🟢 Phase 3：返回搭建区角落

**目的**：从物料区回到搭建区角落，为 Phase 4 的就地搭建就位。

### 路线

1.  **绝对坐标复位**：沿车身前后轴行进到「Phase 1 零点 Z1 沿该轴退 `0.60 m` 处」。
    *   该时刻里程计 `rel_yaw ≈ 0`（Z1 清零后没转过弯），车身前后轴 = 里程计 `X` 轴，故实际动作为**沿 `−x` 后退 `0.60 m`**，闭环目标即 `X = −0.60`。
    *   **必须用里程计绝对坐标闭环、不能用相对位移**：Phase 2 的视觉微调已把车沿该轴挪到了不确定的位置，只有绝对坐标才能回到确定点位。**本段只能靠前进或后退完成，不得侧移。**
    *   实现上用 `move_abs("x", −0.60)`。
2.  左移 `0.20 m`
3.  原地左转 `90°`（航向角 → `+180°`）
4.  前进 `1.20 m` **撞墙**（匀减速，末端 `0.10 m/s`）
5.  左移 `0.50 m` **撞墙**（匀减速，末端 `0.10 m/s`）
6.  后退 `0.1m`(后退速度为 `0.1m/s`)

### 零点处理

*   第 4、5 步的两处撞墙**均不重置零点**（沿用 Z1）。其后 Phase 4 只有机械臂动作、Phase 5 全部为相对位移，没有绝对坐标段需要新基准。

## 🟢 Phase 4：搭建橙色块（动态决定层数 k）

**目的**：就地搭建，**层数完全由 Phase 2 的实际抓取结果决定**，并把结果 `k` 记下来交给 Phase 8。

### 三条基本规则

*   **R1 中间框优先**：中间框有块，第一层必须先用它——动作 `Id10`（从中间框搭建第一层）。
*   **R2 侧框先移中**：左侧框的块必须先经 `Id16`（左框 → 中间框）、右侧框的块必须先经 `Id17`（右框 → 中间框）移到中间框，**再由 `Id10` / `Id11` / `Id12` 执行「搭建第 N 层」**。禁止直接从侧框搭建。
*   **R3 层号递增**：第 `n` 个可用的块搭第 `n` 层，层号连续、不跳号。

### 可用块顺序

| 中间框（`grab_near_M`） | 取块顺序 | 说明 |
| --- | --- | --- |
| 有 | **中 → 右 → 左** | 中间框先搭第一层；随后右侧框经 `Id17` 移中搭第二层，左侧框经 `Id16` 移中搭第三层 |
| 无 | **左 → 右** | 原文指定：中间框没块时**先查左侧框**（`Id16` 左→中 → `Id10` 搭第一层）；左框也没有才轮到右侧框（`Id17` 右→中 → 搭第一层） |

### 决策真值表（穷举 8 种情况）

动作缩写：`B1 = Id10`（搭第 1 层）、`B2 = Id11`（搭第 2 层）、`B3 = Id12`（搭第 3 层）、`L2M = Id16`（左→中）、`R2M = Id17`（右→中）。

| # | 左框 | 中框 | 右框 | 动作序列 | 结果 `k` |
| :-: | :-: | :-: | :-: | --- | :-: |
| 1 | ✅ | ✅ | ✅ | `B1` → `R2M` → `B2` → `L2M` → `B3` | **3** |
| 2 | — | ✅ | ✅ | `B1` → `R2M` → `B2` | **2** |
| 3 | ✅ | ✅ | — | `B1` → `L2M` → `B2` | **2** |
| 4 | — | ✅ | — | `B1` | **1** |
| 5 | ✅ | — | ✅ | `L2M` → `B1` → `R2M` → `B2` | **2** |
| 6 | ✅ | — | — | `L2M` → `B1` | **1** |
| 7 | — | — | ✅ | `R2M` → `B1` | **1** |
| 8 | — | — | — | *（无动作）* | **0** |

### 结果

*   搭建完成后记录 **`k`（`0 ~ 3`）**，供 Phase 8 使用。
*   此时机上一/中/右侧框**均为空**。

## 🟢 Phase 5：上高台准备并抓取紫色块（建立零点 Z2）

**目的**：从搭建区绕上高台，把紫块抓入左侧框。

### 路线（全部为相对位移，不使用绝对坐标）

1.  右移 `0.20 m`
2.  后退 `0.60 m`
3.  原地左转 `180°`（航向角 → `0°`）
4.  右移 `1.70 m`
5.  前进 `1.70 m`
6.  左移 `0.50 m` **撞墙** → **标记撞墙位置为绝对零点 Z2**（`odom_reset`）

### 视觉微调与抓取

*   **摄像头**：**低位摄像头**（视觉目标 `purple`、`camera = "low"`）。
*   沿车身前后轴前进/后退微调（`GRAB_SPEED`、最远 `GRAB_MAX`，未检测到则反向重探；任一方向顶墙则当次扫描立即结束），对齐后调用 **`Id1`（抓紫色块 → 左侧框）**。整段在 `heading_hold,0` 下执行。

## 🟢 Phase 8：再搭建两层（依据 Phase 4 的 k 动态决策）

**目的**：在 Phase 4 已搭好 `k` 层的基础上继续往上搭，最终形成一座塔。**层数与取块来源完全由 Phase 4 的 `k` 与 Phase 5/6 的实际抓取结果决定。**

动作缩写：`B1 = Id10`、`B2 = Id11`、`B3 = Id12`、`B4 = Id13`（搭第 4 层）、`B5 = Id14`（搭第 5 层）、`L2M = Id16`、`R2M = Id17`。

### 情况 1：`k = 3`

在第 3 层基础上搭第 **4、5** 层。

**第 4 层**（用橙块）：

| 条件 | 动作序列 |
| --- | --- |
| `grab_far_M`（中间框有块） | `B4` —— 直接搭建第 4 层 |
| `grab_far_M` 失败但 `grab_far_R` 成功 | `R2M` → `B4` —— 右框的块先移入中间框，再搭建第 4 层 |
| 中、右橙块都没抓到 | **第 4 层搭不成** |

**第 5 层**（用紫块）：`L2M` → `B5`。

*   **例外**：若上面中、右橙块都没抓到（即第 4 层没搭成），则把这块紫块**直接搭到第 4 层**（`L2M` → `B4`），而不是第 5 层——层号必须连续、不能跳号。

**结果**：橙块齐 → 5 层；只有紫块 → 4 层；紫块也没有 → 仍是 3 层。

### 情况 2：`k ≤ 2`

**往上搭 3 层**，可用块按 **中橙 → 右橙 → 左紫** 的顺序取用（**紫色块一定是最后抓、最后搭的**）：

```
可用块序列 = [ 中橙(若 grab_far_M),  右橙(若 grab_far_R),  左紫(若 grab_purple) ]
层数 n = min(可用块个数, 3)          # 抓到几个就搭几层，依次顺延
第 i 个块（i 从 0 起）→ 搭建第 (k + 1 + i) 层：
    中橙:  直接搭建
    右橙:  R2M → 搭建
    左紫:  L2M → 搭建
```

各 `k` 取值下的层号到动作的对应：

| `k` | 依次搭建的层号 | 依次使用的动作 |
| :-: | --- | --- |
| 0 | 1 → 2 → 3 | `B1` → `B2` → `B3` |
| 1 | 2 → 3 → 4 | `B2` → `B3` → `B4` |
| 2 | 3 → 4 → 5 | `B3` → `B4` → `B5` |

*   每层实际用哪个块，取决于该位置对应的抓取是否成功；**缺一块就少搭一层，层号依次顺延**。
*   `k = 2` 且三块全在时，塔高正好到 5 层。

> **注**：按原文，情况 2 是「往上搭 3 层」。因此 `k = 1` 时最终为 4 层、`k = 0` 时为 3 层，**并不补足到 5 层**——这是否符合预期见文末待确认第 7 条。

### 实现用的统一规则（两条合并成一条）

上面两种情况可以写成同一条规则，代码里只实现这一条即可（`config.py` 的 Phase 8 注释与之逐字对应）：

1. 这批要搭 **`n = min(手上可用的块数, PHASE8_EXTRA_LAYERS_BY_K[k])`** 层；
2. **紫块永远占这批的最高一层**（第 `k + n` 层）——紫色是封顶块；
3. 其余 `k+1 … k+n-1` 层由橙块**从下往上**补，顺序**中框 → 右框**；
4. 块不够就少搭几层，层号从 `k+1` 起连续、不跳号。

> ⚠️ 别写成「橙块优先、紫块垫底」。`k = 3` 且中、右橙块都在时，那样会把右框的橙块顶上第 5 层、紫块反而搭不上，与情况 1 不符——正解是**只取中框的橙块搭第 4 层，右框那块不动**。

| 7 | 右转 90° | — | `−180°` |
| 7 | 前进 2.8 | `(+0.500, −2.700)` | `−180°` |
| 7 | 右移 1.6 | `(+0.500, −1.100)` | `−180°` |
| 7 | 前进 1.3 撞墙 | `(−0.800, −1.100)` | `−180°` |
| 7 | 左移 0.5 撞墙 | `(−0.800, −1.600)` | `−180°` |
| 7 | 后退 0.1 | **角落 B = `(−0.700, −1.600)`** | `−180°` |

> 与旧版推导稿的区别：Phase 3 / 7 末尾各多了新加的 `后退 0.10 m`，因此 Phase 5 之后的所有 X 坐标整体平移 `+0.10 m`（Z2 由 `+2.200` 变 `+2.300`，Z3 由 `+3.400` 变 `+3.500`）。

### 闭合核对

| 项目 | 数值 |
| --- | --- |
| 三个零点 | `Z1 = (+1.300, −0.200)`、`Z2 = (+2.300, −2.300)`、`Z3 = (+3.500, −2.700)` |
| 起跑点 → 角落 A（Phase 3 落点） | 约 `1.30 m` |
| 角落 A ↔ 角落 B **外推值之差** | `ΔX = −0.700 m`、`ΔY = −0.300 m` —— **这是行程上限之差，不是落点之差** |

**为什么这个 Δ 不是真实偏差**：Phase 3 与 Phase 7 的收尾航向是 `+180°` 与 `−180°`，**在 `mod 360°` 下是同一个朝向**；两者收尾的两段动作也逐字相同：

```text
前进撞墙（沿世界 −X）  →  左移撞墙（沿世界 −Y）
```

所以只要这两段探墙时**确实碰到了墙**，车就停在**同一面（−X 向）墙与同一面（−Y 向）墙的交点**上——Phase 3 与 Phase 7 落到同一个物理角落，与 `1.20 / 1.30`、`0.5 / 0.5` 这些行程上限无关。上表两个外推点相距 `0.7 m`，只是说明「若前方无墙、各自跑满行程会停在哪」。

### 探墙余量（真正要盯的东西）

真实落点由墙决定，所以唯一会出事的情况是**某一段在碰到墙之前就把行程跑完了**（`run_wall_hit` 会打印「未接触就走到行程上限」的警告）。各段需要的行程 = 起点到墙面的距离：

| 探墙段 | 起点 | 行程上限 | 需要的距离（墙面在「外推角落」时） |
| --- | --- | :-: | --- |
| Phase 3 前进 | `X = +1.100` | `1.20 m` | `1.20 m`（**刚好用满，最紧**） |
| Phase 3 左移 | `Y = −0.800` | `0.50 m` | `0.50 m`（**刚好用满，最紧**） |
| Phase 7 前进 | `X = +0.500` | `1.30 m` | `0.60 m`（余量充足） |
| Phase 7 左移 | `Y = −1.100` | `0.50 m` | `0.20 m`（余量充足） |

> 结论：**Phase 3 的两段是余量最小的一档**，Phase 7 的两段余量很宽。现场若看到撞墙超时/行程跑满的警告，先怀疑 Phase 3 的两段（必要时把 `1.20 → 1.50`、`0.50 → 0.80` 放大，撞墙段放大 `max_dist` 是安全的，车会停在墙上）。反过来说，若要动 Phase 7 的 `2.8 / 1.6`，只需保证外推起点不越过墙面即可。
