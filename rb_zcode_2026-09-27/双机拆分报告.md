## 1. 拆分方案（对应要求 1）

### 1.1 职责划分

| | 树莓派 4B (4GB) — 主控 | 香橙派 4 Pro (6GB) — 视觉节点 |
|---|---|---|
| 运行 | 行为树、19 段轨迹、底盘 A 板串口 115200、LeArm 串口 9600、Tkinter GUI | USB 相机采帧（强制 1280×720）、YOLO 推理（best.pt, imgsz=416） |
| 依赖 | **仅 python3-tk + python3-serial**（标准库实现通信） | torch 2.9.0 / ultralytics 8.4.157 / numpy 1.26.4 / opencv 4.11（版本组合沿用踩坑记录，见其 requirements.txt） |
| 内存 | **~100MB 级**（torch 全家桶 300~700MB 全部卸掉） | 模型进程 ~500MB（6GB 充裕） |
| 角色 | TCP 客户端（`vision_client/remote_vision.py`） | TCP 服务端（`vision_node/vision_server.py`，监听 :9000） |

### 1.2 通信协议（详见 docs/通信协议_树莓派-香橙派.md）

- TCP + UTF-8 JSON 行协议，三条指令：`ping`（链路测试）/ `detect`（采帧+推理，返回原图 1280×720 像素系坐标，与 target_u/v 标定系一致，**零换算**）/ `status`（节点自检）。
- 推荐网线直连静态 IP（树莓派 192.168.50.1 / 香橙派 192.168.50.2），避开赛场 2.4G 干扰；WiFi 方案只改 GUI 输入框里的 IP。

### 1.3 拆分时顺带的树莓派瘦身

`vision/` 目录（相机/YOLO 封装）、best.pt、`_test_vision.py` 都不在树莓派包里；
GUI 的「视觉节点 IP/端口」输入框与「测试视觉链路」按钮替代了原来的本地模型加载。

## 2. 性能与鲁棒性（对应要求 2）

### 2.1 内存收益（核心目标）

| 方案 | 树莓派进程峰值 | 说明 |
|---|---|---|
| 单机版（上一轮） | ~700MB | torch+ultralytics+cv2 常驻 |
| 双机版（本轮） | **~100MB 级** | 仅 tkinter+pyserial+业务对象；4GB 系统余量充足，不触发 swap |

### 2.2 通信链路鲁棒性

- 客户端：连接超时 3s / 请求超时 6s 分离；失败自动重连一次再重发（新 socket，应答不错位）；
  每次请求记录 RTT 与最近错误；
- **异步检测**：行为树通过 detect_async/poll_detect 在后台线程完成请求，GUI 20ms 轮询和
  急停按钮全程不被阻塞（同步 detect/ping 仅 GUI 手动测试用，且异步在途时拒绝并发）；
- 服务端：连接断开不退出；连续 5 次采帧失败重建相机、连续 3 次推理异常重建模型（成功即清零）；
  **非对象/非法 JSON/未知指令一律安全应答，进程绝不崩**（有专项测试用例）；
  空闲超时 120s（任务前半段纯轨迹 >60s 不发请求也不踢连接）；先 listen 再加载模型（加载期可连）。

### 2.3 行为层修复（本轮 + 审查修复）

子代理对抗审查发现 2×P0、3×P1、10×P2，已全部修复或评估：

| 级别 | 问题 | 修复 |
|---|---|---|
| P0-1 | 一行 `123\n` 就能让视觉节点进程崩（AttributeError 逃逸） | 请求类型校验 + 安全应答，专项用例覆盖 |
| P0-2 | 「视觉不可达退化为纯轨迹」只是文档承诺，实际会插必失败的抓取动作拖 ~40s 后任务失败 | 任务编排现在检查 `vision.connected`，未连通真正不插抓取（仿真日志已验证） |
| P1-1 | 伺服中按「暂停→恢复」必杀死任务（move:cancelled 被判 fatal） | 与轨迹段同语义：重发剩余步进续跑 |
| P1-2 | GUI 主线程同步 detect，急停最坏延迟 ~9s | 异步检测（见 2.2），急停始终响应 |
| P1-3 | 相机"丢旧帧"依赖驱动支持 BUFFERSIZE=1，很多 UVC 驱动不理会 → 伺服读到移动前残影 | capture() 固定连排 3 帧再读，对任何驱动安全 |
| P2×10 | 模型失败计数不重置、空闲 10s 踢连接、warmup 阻塞 listen、watchdog 触发时的 NameError、任务运行中可重复开始、GRIP 异常无保护、测试脚本跨目录依赖等 | 全部修复 |

### 2.4 继承上一轮的全部单机优化

19 段轨迹驱动核心、视觉伺服状态机（重试/ACK/静止缓冲）、300s 看门狗、轮询异常保护、
串口 write_timeout、失败路径停车停臂等上一轮修复全部保留并随拆分迁移。

## 4. 部署步骤（两台各 10 分钟）

**香橙派**（先起视觉端）：
```bash
# 静态 IP 192.168.50.2/24（nmtui/netplan）
pip3 install -r vision_node/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
cd vision_node
python3 _test_vision_node.py      # 8 项自测应全过
python3 vision_server.py          # 常驻（建议 systemd 开机自启）
```

**树莓派**：
```bash
# 静态 IP 192.168.50.1/24；装 udev 规则（docs/99-robot-usb-serial.rules）
sudo apt install -y python3-tk python3-serial     # 全部依赖
cd robogame_project
python3 _sim_test_headless.py     # 赛前冒烟（无硬件）
python3 main.py                   # 连接 → 「测试视觉链路」显示"正常 (xms)" → 开始任务
```

## 5. 真机联调注意（继承上轮 4 项标定 + 本轮新增）

1. 上轮 4 项仍然有效：u_sign/v_sign、机械臂 0x06 帧格式、ARMED 时序、target_u/v 复核；
2. **新增**：香橙派相机与标定一致性——`status` 指令应回报 `frame: 1280x720`，若实机相机
   只能出其他分辨率，需重标 target_u/v；
3. **新增**：赛前先按「香橙派上电 → 视觉节点就绪 → 树莓派连接」顺序上电；节点未就绪时
   树莓派任务会自动退化为纯轨迹（有日志提示），不会卡死但也没有抓取分；
4. 若扩大 pick_tasks（多块抓取），注意协议文档 §4 的看门狗余量提醒（链路断开时每个
   抓取动作最坏 ~56s）。
