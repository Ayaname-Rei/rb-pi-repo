# 通信协议：树莓派 ↔ 香橙派 视觉链路（v1，2026-09-24）

## 1. 链路形态

```
┌─────────────────────────┐        TCP / JSON 行协议          ┌──────────────────────────┐
│ 树莓派 4B (4GB)  主控     │ ────── 192.168.50.2:9000 ──────▶ │ 香橙派4 Pro (6GB) 视觉节点 │
│ 行为树/底盘串口/机械臂     │ ◀───── 检测结果 (毫秒级) ──────── │ 相机采帧 + YOLO 推理       │
│ vision_client (标准库)    │                                  │ vision_server             │
└─────────────────────────┘                                  └──────────────────────────┘
```

- **服务端**：香橙派 `vision_node/vision_server.py`，监听 `0.0.0.0:9000`，逐请求顺序处理。
- **客户端**：树莓派 `vision_client/remote_vision.py`（`RemoteVisionService`），纯标准库（socket+json）。
- **推荐组网**：网线直连 + 静态 IP（树莓派 `192.168.50.1` / 香橙派 `192.168.50.2`），避开赛场 2.4G 干扰；
  若用 WiFi，把树莓派 `VisionLinkConfig.vision_host` 改成香橙派的 wlan IP。
- **地址配置**：树莓派侧在 GUI「视觉节点」输入框（默认 `192.168.50.2:9000`）；香橙派侧在 `server_config.py`。

## 2. 帧格式

- 编码：UTF-8 JSON 单行 + `\n` 结尾；请求、应答同构。
- 长度上限：256KB（超长视为链路异常断开）。
- 客户端连接参数：`TCP_NODELAY` 开启；连接超时 3s；请求超时 6s（一次 detect = 采帧+推理，
  香橙派上 0.3~1s，首帧更慢）。

## 3. 指令

### 3.1 ping —— 链路测试
```json
→ {"cmd": "ping"}
← {"ok": true, "pong": true, "t": 1790259356.77}
```

### 3.2 detect —— 采一帧 + 推理一次（核心指令）
```json
→ {"cmd": "detect", "conf": 0.5}
← {"ok": true, "dets": [
     {"class_id": 0, "name": "Purple_Block", "cx": 941.2, "cy": 366.5,
      "x1": 890.0, "y1": 315.0, "x2": 992.0, "y2": 418.0, "conf": 0.83}
   ], "infer_ms": 412.6}
← {"ok": false, "error": "采帧失败"}          # 相机掉线等
```
- `conf` 由树莓派 `VisionConfig.conf_threshold` 下发，服务端限幅到 [0.01, 0.99]。
- **坐标系**：cx/cy 为原图 1280×720 像素坐标，与树莓派 `VisionConfig.target_u/v`（940.5, 366.0）
  同一坐标系，两侧无任何换算。分辨率由香橙派 `server_config.py` 强制设置，改分辨率必须
  同步重标 target_u/v。

### 3.3 status —— 节点自检（调试用）
```json
→ {"cmd": "status"}
← {"ok": true, "camera_ready": true, "model_ready": true,
   "imgsz": 416, "frame": "1280x720", "uptime_s": 37.9}
```

未知 `cmd` → `{"ok": false, "error": "未知指令: ..."}`；非法 JSON → `{"ok": false, "error": "请求不是合法 JSON"}`。

## 4. 鲁棒性行为（两侧各自的职责）

**树莓派客户端**：
- 行为树走**异步检测**（detect_async + poll_detect）：请求在后台线程执行，
  GUI 20ms 轮询与急停按钮全程不被阻塞；
- 请求失败（连接断/超时/应答损坏）自动重连一次再重发，仍失败返回 None；
  重连是新 socket，旧请求的迟到应答不会错位成新应答；
- 每次成功请求记录 `last_rtt_ms`，失败记录 `last_error`（GUI「测试视觉链路」按钮可查）；
- detect 返回 None 时，上层 `VisualPickAction` 还有 5 次检测重试（间隔 0.3s）兜底；
- 同步 detect/ping 在异步请求在途时会拒绝执行（防两个线程写同一 socket）。

**香橙派服务端**：
- 连接断开不退出进程，循环等待下一个客户端（树莓派随时可重连）；
- 连续 5 次采帧失败 → 重建相机（应对 USB 掉线）；连续 3 次推理异常 → 重建模型（成功即清零）；
- 非对象 JSON / 非法 JSON / 未知指令：应答 `{"ok": false, "error": ...}`，进程绝不崩溃；
- 客户端空闲超时 120s（任务前半段纯轨迹可能 >60s 不发请求，不能踢连接）；
- 先 listen 再加载模型：加载 10~30s 期间端口可连、请求在 backlog 排队。

**退化语义（已实现）**：连接底盘时若视觉节点 ping 不通或机械臂串口打不开，
任务编排**不插入抓取动作**，本次任务按纯轨迹模式执行（GUI 与运行日志双重提示）；
任务中途节点死掉则由检测重试 + 300s 看门狗兜底停车。

**看门狗**：任务级 300s 强制停车停臂，任何一端死机都不会让车失控。
注：单个抓取动作在链路彻底断开时最坏 ~56s（6 次检测 × 9s + 间隔），
当前 1 个抓取任务安全；若把 pick_tasks 扩到 3 项，需重估 300s 看门狗余量。

## 5. 时序约定（视觉伺服）

```
树莓派: CHECK_STILL(静止缓冲0.5s) → detect 请求 ──▶ 香橙派: grab丢旧帧 → read → YOLO → 应答
        ← 检测坐标（原图像素系）
        误差→步进 move(0.03/0.01m) → 等 ACK → 回到 CHECK_STILL
        |误差|<15px×2 → run_group(机械臂动作组) → 盲等12s → SUCCESS
```
一次 detect 请求（含采帧）在有线直连下总延迟 ≈ 香橙派推理耗时 + <1ms 传输，
不会成为伺服循环的额外瓶颈。
