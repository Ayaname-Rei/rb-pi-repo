# RoboGame 2026：麦克纳姆轮机器人室内导航设计与实车落地方案

**文档版本**：v1.0  
**适用场景**：RoboGame 2026 竞技组 (7.2m × 4.8m 场地，5cm 黑线，6个墙面视觉标签)  
**硬件架构**：树莓派 4B (主控) + STM32 A板 (底层) + USB 广角摄像头 + 底盘红外传感器阵列 + IMU 

---

## 1. 核心导航挑战与总体架构设计

麦克纳姆轮底盘在提供优异全向机动性的同时，也带来了严重的**运动学滑移问题**（纵向滑移 2%~5%，横向侧滑高达 8%~15%）。如果仅依赖纯轮式里程计（Dead Reckoning），在全场 14 米的长途奔袭后，累积误差将导致机器人完全偏离抓取工位。

针对我们的硬件条件（算力有限的树莓派 4B + 强实时性的 STM32），我们**放弃沉重且易崩溃的纯视觉 SLAM（如 ORB-SLAM）**，采用业界顶尖车队（RoboMaster、FRC）主流的 **“分层互补、四重融合”** 轻量化导航架构：

1. **基础层（STM32，100-500Hz）**：轮式里程计 + IMU 航向强锁死（防滑移基石）。
2. **局部引导层（STM32，200Hz）**：高频红外对管阵列横向巡线（确保走廊极高循迹精度）。
3. **全局纠偏层（树莓派 4B，20-30Hz）**：墙面 ArUco / AprilTag 标签 PnP 定位（消除全局长程累计漂移）。
4. **融合决策层（树莓派 4B，50Hz）**：2D 扩展卡尔曼滤波 (EKF) 与行为树状态机调度。

## 2. 模块一：麦轮里程计与 IMU 航向锁死 (Yaw Lock)

麦轮最脆弱的死穴是“航向耦合”——哪怕航向角（Yaw）仅仅漂移 $5^\circ$，前进 1 米时就会无中生有地产生约 8.7 厘米的横向虚假位移。

### 2.1 设计方案
*   **重力加速度计无法约束 Yaw 轴**，室内磁力计受电机严重干扰不可用。必须依靠**高频去零偏后的单轴角速度（Gyro Z）梯形积分**。
*   **开机静止校准（ZUPT）**：开机后强行静止 2 秒，采集 200~500 个采样点计算零偏基准，并在积分时扣除，可将漂移率压制在 $< 0.5^\circ / \text{min}$。
*   **横移解耦 PID**：底盘在响应平移指令时，底层自动介入航向 PID 纠偏。**坚决不允许底盘在横向平移或直行中发生自发漂转**。

## 3. 模块二：基于 5cm 黑线的全向巡线与路口决策

传统差速车巡线必须靠“车头转向”对准线，易产生蛇形震荡。麦克纳姆轮则可实现**全向平移解耦巡线**——车身永远朝前（$\omega_z = 0$），仅靠侧向滑移（$v_y$）修正偏差。

### 3.1 传感器选型与排布
*   **摒弃摄像头巡线**：视觉巡线在树莓派上存在 30~60ms 延迟，会导致麦轮在高速下震荡。
*   **采用红外反射阵列（如 TCRT5000 / QTR-8A）**：直接接入 STM32 的 ADC DMA，实现 $<1\text{ms}$ 的零延迟。
*   **阵列规格**：针对 5cm 黑胶带，推荐 **10~12 路传感器，间距 8~10mm**，离地高度约 3mm，外加 3D 打印黑色遮光裙边。这样能保证始终有 5~6 个探头在黑线上，提供连续线性的偏差输出。

### 3.2 巡线控制逻辑
1.  **连续加权质心法**：不使用二值化判断，而是利用模拟量 ADC 值进行加权平均，计算出亚毫米级的横向偏移量 $e_y$。
2.  **双闭环控制**：
    *   $v_x$：恒定前行速度（如 $0.5\text{m/s}$）。
    *   $v_y = K_{p} \cdot e_y + K_{d} \cdot \Delta e_y$：纠正横向偏差，消除侧滑。
    *   $\omega_z = -K_{p, \theta} (\theta_{\text{IMU}} - \theta_{\text{target}})$：保持车体绝对平直。

### 3.3 十字 / T字路口决策盲走
*   当阵列中大量传感器（如 $\ge 10$ 个）同时检测到黑线，说明到达十字路口。
*   **盲走越过（Blind Traverse）**：此时必须**冻结**横向巡线 PID，依靠里程计和 IMU 盲走 8~10cm，直到越过交叉黑斑后再恢复闭环，防止车身被侧向支线强行拖拽。

## 4. 模块三：ArUco/AprilTag 全局视觉定位

墙面的 6 个 15×15cm 视觉标签是消除机器人长途盲走漂移的绝对“锚点”。

### 4.1 算法选型与树莓派优化
*   **字典选择**：推荐使用 **AprilTag `tag36h11`**（几乎零误识别）或 **ArUco `DICT_4X4_50`**。
*   **PnP 解算避坑**：标准 `solvePnP` 在正对标签时易发生“平面法向量翻转二义性”（位姿在两面镜子间反复横跳）。必须使用 `cv2.SOLVEPNP_IPPE_SQUARE` 算法。
*   **树莓派算力优化**：
    *   使用 `cv2.VideoWriter_fourcc(*'MJPG')` 降低 USB 带宽。
    *   将 1280×720 原图降采样为 640×360 进行粗检测，再切出 ROI 在原图做亚像素角点精炼，可稳定实现 25-30 FPS。

### 4.2 精度模型与协方差膨胀
视觉深度测量的误差随距离平方发散：在 0.5m 处误差仅 $\pm 3\text{mm}$，在 2m 处可达 $\pm 4.5\text{cm}$。
*   **马氏距离门限（Mahalanobis Gating）**：若视觉解算出的位姿与当前推算位姿相差过大（$D_M^2 > 7.815$），直接果断丢弃该帧，防止误识别导致飞车。
*   **大倾角剔除**：当相机观测标签的角度 $> 50^\circ$ 时，PnP 深度解算失真，应降低该观测权重或直接舍弃。

## 5. 模块四：多传感器融合 (EKF) 与实战落地

将高频/低精度的 STM32 遥测数据与低频/高精度的树莓派视觉数据结合。

### 5.1 融合机制 (Filter Strategy)
1.  **预测步（100Hz）**：基于底层上报的轮式解算位移和 IMU 航向进行外推。
2.  **更新步（20Hz，当可见标签时）**：使用 ArUco 结算出的全局 $(x, y, \theta)$ 对当前状态进行卡尔曼增益平滑修正。
3.  **坐标重置（黑线触发）**：当机器人进入物料区/搭建区时，由车底外侧红外传感器捕捉到边界黑线的瞬间，对 $x$ 或 $y$ 坐标进行**一次性强制赋值硬重置 (Hard Reset)**，为最终的机械臂抓取提供毫米级的物理对位精度。

### 5.2 实际代码落地方案（建议按以下四个 Phase 推进）
*   **Phase 1：打通 IMU 航向闭环（本周完成）**
    *   在 `core/chassis_driver.py` 与 STM32 中，加入 Z 轴陀螺仪锁死功能，确保用遥控器推动车体平移时，车头不会出现一丝旋转。
*   **Phase 2：集成红外巡线阵列（下周一）**
    *   采购 8-12 路连续横排红外对管，接入 STM32 ADC。实现无转向的纯侧移巡线。
*   **Phase 3：部署 ArUco / AprilTag 节点（下周中）**
    *   在树莓派端实现摄像头 PnP 测距定位节点。在场地墙壁张贴标签，完成内参标定。
*   **Phase 4：基于 EKF / Offset 的 FSM 状态机串联（比赛前）**
    *   通过 `WorldModel` 类整合上述数据流，形成：起步（巡线） $\to$ 长直道（加速巡线+盲跨路口） $\to$ 接近工位（ArUco 减速纠偏） $\to$ 工位入场（黑线触发急停硬校准）的自动化闭环。
